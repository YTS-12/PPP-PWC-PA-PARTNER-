# PwC PA Partner (PPP)

Who's next, 다음 제안 후보.

DART 공시를 신호로 읽어서 회계·결산 지원(PA) 같은 비감사 용역을 제안할 만한 상장사를 골라 주는 웹앱입니다. 삼일회계법인 2026 Discover 신규입사자 연수 조별과제(C-2조)로 만들었습니다.

- 앱: https://ppp-rose-two.vercel.app (2026-10-30까지 유지, 로그인 없이 '둘러보기' 가능)
- 시연 영상: https://drive.google.com/file/d/1cugniGkGQpbXTRUOT9D3OhwzVODDa3n4/view?usp=sharing
- 설계서: [docs/design.md](docs/design.md) · 실행·수집·배포 방법: [docs/operations.md](docs/operations.md)

## 어떤 문제를 풀려고 했나

회계·결산 지원과 내부회계관리제도 구축은 독립성 때문에 삼일이 감사하는 회사에는 제공할 수 없습니다. 그래서 영업은 '다른 법인이 감사하는 회사 중 지금 이런 용역이 필요할 만한 곳'을 찾는 데서 시작합니다.

그런데 그 단서(제출기한 연장, 주기적 지정 도래, 합병·분할, 횡령·배임 공시 등)는 DART 곳곳에 흩어져 있습니다. 후보를 하나씩 열어 확인하다 보면 결산 전 4분기나 지정감사 통지 직후 같은 적기를 놓치기 쉽고, 새 타깃 발굴은 결국 감과 인맥에 기대게 됩니다. CFO를 만나려면 "왜 지금 이 회사인지" 설명할 근거도 필요합니다.

PPP는 상장사 2,555곳의 공시를 한 번에 걸러서 타깃·근거·적기·진행 상태를 한 화면에 모읍니다. 수임 흐름(발굴 → 독립성 확인 → 파트너·CFO 미팅 → 제안 → 수임심사 → 계약) 가운데 '발굴과 근거 정리'까지만 맡고, 그 뒤는 사람이 합니다.

## 누가 쓰나

- 비감사 자문 매니저(PA·내부회계·IFRS 18): 새 타깃을 찾고 제안을 총괄합니다. 주 사용자입니다.
- 1~3년 차 스태프: 공시·재무 리서치와 제안서 초안을 맡습니다.
- 파트너: 매니저가 CSV로 넘긴 목록을 보고 타깃을 승인하고 CFO를 만납니다.

## 화면과 기능

| 화면 | 하는 일 |
| --- | --- |
| 대시보드 | 용역별 후보 수와 최근 3개월 신호 공시를 한눈에 봅니다. |
| 추천 목록 | 용역·신호·시장·업종·자산 규모로 거르면 후보가 점수순으로 나옵니다. 점수는 서로 다른 근거의 수입니다. 삼일 감사 고객은 기본으로 숨깁니다. |
| 기업 분석 | 신호별 근거 공시와 DART 원문 링크, 재무 요약, 감사인 이력, 대표 연락처를 한 화면에 모았습니다. 제안 방향 초안과 메모를 쓸 수 있습니다. |
| 내 후보 | 저장한 회사의 진행 상태(검토 전 → 검토 중 → 제안 대상 / 제외)와 메모를 관리하고 CSV로 내보냅니다. |

로그인 없이 모든 기능을 쓸 수 있습니다. 다만 둘러보기 상태에서 저장한 내용은 새로고침하면 사라집니다. 이메일과 비밀번호로 로그인하면(계정이 없으면 그 자리에서 만들어집니다) 조건·후보·메모가 계정에 남습니다.

## 용역과 신호

용역 4개마다 공시 신호를 3개씩, 모두 12개를 둡니다. 정의와 기준값, 화면 문구는 `config/signals.json` 한 곳에서만 관리합니다.

| 용역 | 신호 |
| --- | --- |
| 회계·결산 지원(PA) | 사업보고서 제출기한 연장신고 이력 · 주기적 지정 도래·첫해 추정 · 합병·분할·영업양수도 결정 |
| 내부회계관리제도 | 2029년 연결 내부회계 감사 대상 · 횡령·배임 관련 공시 · 합병·분할·영업양수도 결정(통제 통합) |
| IFRS 18 도입 지원 | 영업외손익 비중 큼 · 지주회사·금융업 · 자산 5천억 원 이상 + 연결 |
| 재무자문·구조조정 | 부도·회생·채권은행 관리·거래소 조치 공시 · 감사의견 비적정 · 자본잠식 50% 이상 |

2026-10-06 데이터 기준으로 2,555곳 중 1,077곳에 신호가 하나 이상 있습니다.

## 데이터

코스피·코스닥 상장사 2,652곳에서 스팩·리츠·인프라펀드를 뺀 2,555곳이 대상입니다. OpenDART API와 DART 공시 화면에서 받은 공시만 쓰고, 고객 기밀이나 담당자 개인정보는 담지 않습니다. 대표자명은 공시된 기업개황 정보입니다.

- 기업개황: 업종, 대표자, 대표전화, 홈페이지, 주소
- 재무: 연결·별도 자산·부채·자본, 매출·영업이익(3개년), 세전이익
- 감사인: 2020~2025 사업연도와 2026 반기 감사인, 2025 감사의견
- 공시: 주요사항보고서·거래소공시(최근 12개월), 제출기한 연장신고(3개년), 정정공시의 최초 공시일과 철회 여부

2026-10-06에 수집한 스냅샷을 정적 JSON(`public/data/`)으로 넣어 두었습니다. 앱이 실행 중에 DART나 외부 API를 부르는 일은 없습니다.

## 알아 둘 제약

- 신호는 공시 규칙으로 고른 추정이며, 용역 수요를 확정하지 않습니다. 추천은 검토 후보입니다.
- 삼일 감사 고객 숨김은 1차 필터입니다. 독립성은 사내 절차(CES)로 최종 확인합니다.
- 현재 감사인을 공시에서 못 찾은 회사는 '감사인 미확인'으로 두고 숨기지 않습니다. 이력상 감사인은 '추정'으로 표시만 합니다.
- 데이터는 2026-10-06 기준이고 자동으로 갱신되지 않습니다.

## 만든 방법

Next.js 15(App Router, TypeScript)로 만들고 Vercel에 배포했습니다. 로그인과 개인 저장은 Supabase를 쓰고(테이블 4개, RLS 적용), 공시 데이터는 DB 없이 정적 파일로 제공합니다.

구현은 Claude Code로 했습니다. 먼저 설계서(`docs/design.md`)와 규칙 파일(`CLAUDE.md`: 비밀 키 금지, 실행 중 API 호출 금지, 신호 문구는 설정 파일에서만, 독립성 규칙)을 쓰고, 그 기준대로 구현하고 점검하기를 반복했습니다. 기준값을 정할 때는 근거와 영향을 먼저 받아 보고 골랐습니다. 예를 들어 영업외손익 신호는 처음에 1,170곳이 잡혀서, 영업이익 대비 50%·100억 원 기준으로 조정해 417곳으로 줄였습니다.

## 검증하면서 고친 것

10/5와 10/6 두 번 모여 점검했습니다. 2차 점검에서는 표본 56건을 DART 원문과 대조했습니다. 그때 고친 것 중 큰 것은 아래와 같습니다.

- 정정공시를 정정일이 아니라 최초 공시일 기준으로 세고, 철회·취하된 결정은 신호에서 뺐습니다.
- 2026 반기 감사인 API가 비어 있는 회사(101곳)를 감사용역 체결현황 API와 DART 공시 화면으로 보완했습니다. 미확인이 36곳에서 10곳으로 줄었고, 삼일 고객으로 잘못 숨겨졌던 회사도 바로잡았습니다.
- 감자·영업정지는 재무위험 신호가 함께 있을 때만 인정하고, 영업정지에 따라 자동으로 걸리는 매매거래정지는 근거에서 뺐습니다.
- 3/1~3/19에 접수된 연장신고 누락과 360px 화면의 가로 넘침을 고쳤습니다.

## 직접 실행하기

Node.js 24가 필요합니다.

```bash
npm install
npm run dev
```

http://localhost:3000 에서 열립니다. `.env` 없이도 둘러보기로 모든 화면을 볼 수 있습니다. 로그인(Supabase), 데이터 다시 만들기(`npm run data:build`), 추가 수집(`npm run collect:*`), Vercel 배포 방법은 [docs/operations.md](docs/operations.md)에 있습니다.

## 폴더 구조

```text
app/                 화면 (로그인, 대시보드, 추천 목록, 기업 분석, 내 후보·설정)
components/, lib/    공통 UI, 점수 계산, 데이터 로딩, Supabase
config/signals.json  용역·신호 정의와 기준값, 화면 문구
scripts/             추가 수집(collect/)과 화면용 데이터 생성(build-data.mjs)
data/                수집 대상 목록(universe.json), 추가 수집 결과(extra/)
public/data/         화면이 읽는 JSON
supabase/            사용자 테이블 SQL
docs/                설계서, 운영 안내, 신호별 용역 수요 근거
```
